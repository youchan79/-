# 오늘의 5명 — 2026 Physical AI Networking Day 네트워킹 매칭

네트워킹 시간 직전에 참가자가 서로의 프로필 카드를 넘겨 보며 **대화하고 싶은 사람 5명**을 고르고,
**나와 대화하고 싶어하는 사람**을 확인하는 웹페이지입니다. 휴대폰 브라우저에서 QR로 접속하며 앱 설치나 회원가입이 없습니다.

## 화면 흐름

틴더와 같은 방식입니다. 어두운 화면, 꽉 찬 카드, 아래쪽 동그란 버튼, 하단 탭(스와이프 / LIKE / 프로필).

| 순서 | 화면 | 내용 |
|---|---|---|
| 1 | 시작 | 이름 → 휴대폰 번호 뒤 4자리 → 참가 안내(프로필 공개·행사 후 삭제) **동의합니다** |
| 2 | 프로필 입력 | 한 화면에 질문 하나씩 8단계: 회사 → 로고 → 직무·분야·연차 → 대표 경험 → 이전 경력 → 나누고 싶은 이야기 → 관심 키워드 → 링크드인(선택) (약 3분) |
| 3 | 대기 | 스와이프 탭에 내 로고와 참여 인원이 보이고, 운영자가 시작하면 바로 카드로 바뀜 |
| 4 | 스와이프 | 오른쪽으로 밀거나 하트 = 대화하고 싶어요, 왼쪽이나 X = 넘기기, 노란 버튼 = 직전 한 장 되돌리기. 카드를 탭하면 다음 페이지(기본 정보 → 경험·경력 → 대화 주제·키워드), 화살표 버튼은 전체 프로필. 5명을 고르면 완료 화면 |
| 5 | LIKE | 나를 고른 사람(서로 고른 사람이 맨 위, 초록 점 '서로 선택')과 내가 고른 사람. 실시간으로 추가됨. 서로 고른 사람은 **링크드인 보기** 버튼이 보임 |
| — | 프로필 | 내 카드 미리보기, 프로필 수정 |
| — | 운영자 (`주소#admin`) | 진행 단계 전환(등록 → 스와이프 → 종료), 등록·완료 인원, 입장 QR, 프로필 숨기기, 예시 참가자 넣기, 전체 초기화 |

- 나를 고른 사람은 **내가 5명을 다 고른 뒤**에만 누군지 보입니다. 그 전에는 LIKE 탭에 흐린 카드와 인원수만 보입니다. 누가 나를 골랐는지 보고 따라 고르는 것을 막기 위해서입니다.
- 카드 순서는 사람마다 무작위입니다. 모든 참가자가 비슷한 횟수로 노출됩니다.
- 내 관심 키워드와 겹치는 키워드는 카드에 분홍색으로 표시됩니다.
- 남은 카드를 다 넘겼는데 5명이 안 되면 그때 끝납니다. 나중에 등록한 사람이 생기면 스와이프 탭에서 이어서 볼 수 있습니다.

### 프로필 카드 구성 (예시)

얼굴 사진 대신 회사 로고가 들어가고, 커리어 정보가 중심입니다.

| 항목 | 예시 | 필수 |
|---|---|---|
| 회사 로고 | 참가 명단의 로고가 자동으로 들어감. 명단에 없으면 직접 업로드, 그것도 없으면 회사 이름 첫 글자 | |
| 회사·기관명 | 택타일웍스 | 필수 |
| 회사가 하는 일 | 촉각 센서 기반 로봇 그리퍼 개발 | |
| 이름 / 직함 | 김도현 / 로봇 데이터 엔지니어 | 필수 |
| 직무 분야 · 연차 | 데이터 · 3~7년 | 필수 |
| 이런 이야기를 나누고 싶어요 | 촉각 데이터 품질 기준을 다른 팀은 어떻게 잡는지 궁금합니다 | 필수 |
| 대표 경험 (최대 3개) | 협동로봇 그리퍼 촉각 데이터 120시간 수집 파이프라인 구축 | 1개 이상 |
| 이전 경력 (최대 3개) | 2018–2021 · 한빛대 지능로봇연구실 · 연구원 | |
| 관심 키워드 (최대 5개) | 촉각 센서, 데이터 수집·라벨링, 매니퓰레이션 | |
| 찾고 있어요 (최대 3개) | 데이터 협력, 정보 교류 | |
| 링크드인 | linkedin.com/in/아이디 (서로 고른 사람에게만 보임) | |

'이런 이야기를 나누고 싶어요'는 대면 대화의 첫마디로 쓰라고 넣은 항목입니다. 결과 화면에서도 이 문장이 함께 보입니다.

## 1. 먼저 시연 모드로 보기

`config.js`의 `firebase`가 `null`인 상태로 열면 **시연 모드**입니다. 가상의 참가자 34명이 들어 있고, 데이터는 그 기기에만 저장됩니다.
오른쪽 위 **DEMO** 버튼에서 진행 단계를 직접 바꿔 볼 수 있고, 운영자 화면 PIN은 `0000`입니다.

## 회사 로고 자동 등록

참가자가 회사 이름을 입력하면 `logos/logos.js` 대응표에서 로고를 찾아 자동으로 넣습니다. 띄어쓰기, 영문 대소문자, (주)·㈜·주식회사는 무시하고 맞추므로 '(주) 왓츠랩'으로 입력해도 '왓츠랩' 로고가 들어갑니다. 대응표에 있는 회사는 입력 화면에서 회사 이름 자동완성도 됩니다.

1. 참가 회사 명단이 확정되면 로고 이미지를 **회사 이름으로 파일 이름을 지어** 모읍니다. 예: `왓츠랩.png`, `택타일웍스.jpg` (PNG·JPG·WEBP·SVG, 정사각형에 가까울수록 좋음)
2. 이미지를 `logos/` 폴더에 넣고 `node tools/build-logos.mjs`를 실행하면 대응표가 만들어집니다. (Claude에게 이미지를 주면 이 작업을 대신 합니다.)
3. 이미 등록한 참가자도 다음에 화면을 열 때부터 새 로고로 보입니다.

## 2. Firebase 준비 (약 10분, 무료)

참가자 35명이 같은 데이터를 보려면 서버가 필요합니다. Google의 Firebase 무료 요금제(Spark)로 충분합니다.

1. <https://console.firebase.google.com> 에 Google 계정으로 로그인 → **프로젝트 만들기**
   - 이름 예: `physical-ai-networking` / Google 애널리틱스는 꺼도 됩니다.
2. 왼쪽 메뉴 **빌드 → Authentication → 시작하기 → 로그인 방법 → 익명 → 사용 설정 → 저장**
   - 참가자는 로그인 화면을 보지 않습니다. 기기마다 보이지 않는 익명 계정이 자동으로 생깁니다.
3. **빌드 → Firestore Database → 데이터베이스 만들기**
   - 위치: `asia-northeast3 (서울)` / 모드: **프로덕션 모드**
4. Firestore의 **규칙** 탭 → 기존 내용을 지우고 이 폴더의 `firestore.rules` 내용을 전부 붙여넣기
   - 붙여넣은 뒤 `'여기에-관리자-PIN'`을 운영진만 아는 값으로 바꾸세요 (8자 이상 권장, 예: `wl-team-b-1116`).
   - **게시** 버튼을 누릅니다.
   - 이 PIN은 콘솔에만 입력하고 GitHub 등 공개된 곳에는 올리지 마세요.
5. 프로젝트 개요 옆 톱니바퀴 → **프로젝트 설정 → 내 앱 → 웹(`</>`) 아이콘 → 앱 등록**
   - 화면에 나오는 `const firebaseConfig = { ... }` 안의 내용을 복사합니다.

## 3. config.js에 설정 붙여넣기

`config.js`를 메모장 등으로 열고 `firebase: null,` 줄을 복사한 값으로 바꿉니다.

```js
  firebase: {
    apiKey: 'AIza...',
    authDomain: 'physical-ai-networking.firebaseapp.com',
    projectId: 'physical-ai-networking',
    storageBucket: 'physical-ai-networking.appspot.com',
    messagingSenderId: '1234567890',
    appId: '1:1234567890:web:abcdef',
  },
```

이 값들은 공개되어도 괜찮은 웹 앱 식별자입니다. 실제 보호는 4번의 보안 규칙이 담당합니다.

## 4. 인터넷에 올리기 (Netlify, 무료)

1. 이 `networking-day` 폴더를 내 컴퓨터에 받습니다 (GitHub → Code → Download ZIP → 압축 해제).
2. 3단계대로 `config.js`를 고칩니다.
3. <https://app.netlify.com/drop> 에 로그인(GitHub 계정 가능) → `networking-day` 폴더를 그대로 끌어다 놓습니다.
4. 몇 초 뒤 `https://무작위이름.netlify.app` 주소가 생깁니다. **Site configuration → Change site name**에서 알아보기 쉬운 이름으로 바꿀 수 있습니다.
5. 나중에 파일을 고치면 Netlify 사이트의 **Deploys** 탭에 폴더를 다시 끌어다 놓으면 됩니다.

## 5. 리허설 체크리스트 (행사 전날까지)

- [ ] `주소#admin` 접속 → 운영자 PIN으로 들어가기 (운영자 기기로 쓸 노트북·휴대폰마다 한 번씩)
- [ ] 운영자 화면 **테스트 → 예시 참가자 34명 넣기** (가상의 사람·회사, 목록에 '테스트' 표시)
- [ ] 운영진 휴대폰 2대 이상으로 프로필 등록 → **스와이프 진행** → 카드 넘기기 → LIKE·서로 선택·링크드인 확인
- [ ] iPhone(Safari)과 Android(Chrome) 둘 다 확인
- [ ] 리허설이 끝나면 **테스트 → 전체 초기화**: 프로필, 고른 기록, LIKE, 링크드인이 모두 지워지고 진행 단계가 **프로필 등록**으로 돌아갑니다. 운영진이 행사 당일 같은 이름·번호로 다시 들어와도 예전 기록은 남지 않습니다.
- [ ] 입장 QR 출력 또는 화면에 띄울 준비 (운영자 화면 → **크게 띄우기**)

## 6. 행사 당일 진행 순서

| 시점 | 운영자 | 참가자 |
|---|---|---|
| 접수 ~ 타운홀 전후 | 진행 단계 **프로필 등록**. 입장 QR을 화면·테이블에 띄움. 운영자 화면에서 등록 인원 확인 | QR 접속 → 프로필 입력 → 대기 화면 |
| 네트워킹 약 10분 전 | **스와이프 진행**으로 변경 (참가자 화면이 즉시 바뀜) | 카드 넘기며 5명 고르기 (3~5분) |
| 네트워킹 시작 | 운영자 화면에서 스와이프 완료 인원 확인 | 결과 화면을 보고 서로 고른 사람부터 찾아가기 |
| 네트워킹 종료 | **종료**로 변경 | 결과 화면만 보임 |

안내 멘트 예: "QR을 찍고 프로필을 만들어 주세요. 네트워킹 10분 전에 카드가 열립니다. 대화하고 싶은 분 5명을 고르면, 나를 고른 분도 확인할 수 있어요."

참가자가 창을 닫거나 다른 기기로 바꿔도 **같은 이름과 뒤 4자리**를 입력하면 자기 프로필과 고른 기록이 그대로 돌아옵니다.

## 7. 행사 후 데이터 삭제

- 보안 규칙에 따라 **2026년 12월 1일부터 모든 읽기·쓰기가 자동으로 막힙니다.** (`firestore.rules`의 날짜로 조정 가능)
- 운영자 화면의 **전체 초기화**로 프로필과 고른 기록을 바로 지울 수 있습니다.
- 본인 확인용 해시까지 남김없이 지우려면 Firebase 콘솔 → **프로젝트 설정 → 일반 → 맨 아래 프로젝트 삭제**가 가장 확실합니다.
- 입장 화면에서 "행사가 끝나면 삭제"에 동의를 받았으므로 행사 후 바로 삭제하세요.

## 보안·개인정보 요약

- **휴대폰 뒤 4자리는 저장하지 않습니다.** 이름과 함께 해시(복원할 수 없는 값)로 바꾼 뒤, 그 해시를 아는 사람만 자기 프로필을 찾을 수 있습니다. 해시 목록은 누구도 조회할 수 없습니다.
- 프로필은 접속한 참가자 누구나 볼 수 있습니다 (그것이 목적이므로). 링크를 아는 외부인도 볼 수 있으니 QR은 행사장 안에서만 공유하세요.
- **누가 누구를 골랐는지는 당사자만 봅니다.** 내가 고른 목록은 나만, 나를 고른 사람은 나와 고른 사람만 읽을 수 있습니다. 운영자 화면에서도 볼 수 없습니다. (Firebase 콘솔에는 프로젝트 주인만 들어갈 수 있습니다.)
- **링크드인 주소는 내가 고른 사람에게만 전달되고, 화면에는 서로 고른 경우에만 보입니다.** linkedin.com 주소만 저장할 수 있습니다.
- 다른 사람 이름으로 고르기를 조작하거나 6명 이상 고르는 것은 서버 규칙이 막습니다.
- 운영자 PIN은 보안 규칙 안에만 있고 웹페이지 코드에는 없습니다.
- 한계: 누군가 다른 참가자의 이름과 휴대폰 뒤 4자리를 알면 그 사람으로 들어올 수 있습니다. 이 행사 규모에서는 감수할 만한 수준으로 판단했습니다.
